# Contributing to Pathlight.ai

First off, thank you for considering contributing to Pathlight.ai! It's people like you that make open source such a great community.

## Where do I go from here?

If you've noticed a bug or have a feature request, make sure to check our [Issues](https://github.com/jayanthkumar10/PathLight.ai/issues) page to see if someone else has already created an issue for it. If not, feel free to open a new one using the provided templates!

## Fork & create a branch
If this is something you think you can fix, then fork Pathlight.ai and create a branch with a descriptive name.

## Get the test suite running
Make sure you have a local environment set up. Read `docs/Development.md` for instructions. Verify that the application boots correctly using Docker.

## Implement your fix or feature
At this point, you're ready to make your changes! Feel free to ask for help on GitHub if you get stuck.

## Make a Pull Request
Once your changes are complete, open a Pull Request. Fill out the Pull Request template comprehensively. 

A maintainer will review your code. We may ask you to make a few changes before merging.

## Code Style Guidelines
- **Python**: Please adhere to PEP-8. We strongly recommend using `black` for formatting and `flake8` for linting.
- **Frontend**: Use semantic HTML and vanilla CSS/JS where possible. Keep the footprint light.
- **Commits**: Write clear, concise commit messages. (e.g., `fix: resolve issue with PDF spacing` or `feat: add mistral model support`).
